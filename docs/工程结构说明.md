# 今日灵签工程结构说明

本项目当前采用轻量静态 H5 结构，线上可直接通过 `docs/` 目录发布到 GitHub Pages，同时保留 Vercel 部署入口。

## 当前核心结构

```text
jinri/
├── README.md
└── docs/
    ├── index.html              # H5 入口页
    ├── styles.css              # 全局视觉样式与移动端适配
    ├── app.js                  # 核心页面渲染、状态流转、交互逻辑
    ├── admin.html              # 试玩数据面板入口
    ├── admin.js                # 本地试玩数据面板逻辑
    └── data/
        ├── categories.json     # 主题与轻场景内容
        ├── moods.json          # 状态选项内容
        └── signs.json          # 签文内容池
```

## 本轮整理后的开发边界

这次重做优先保证 `docs/` 下的 GitHub Pages 静态版本可直接运行，因此没有引入构建工具，也没有强行改成 React / Vite。

原因：

1. 当前仓库已经以 `docs/` 作为备用发布目录。
2. 第一版目标是朋友试玩和视觉验证，静态 H5 足够。
3. 不引入构建链，可以降低部署失败概率。
4. 后续确认视觉和链路后，再迁移到 React 组件工程更稳。

## 本轮 UI 重做内容

### 1. 页面结构

`app.js` 已按完整核心链路重做：

```text
首页
↓
轻场景选择页
↓
状态选择页
↓
抽签页
↓
抽签过渡页
↓
结果页
↓
保存这句签弹层
```

### 2. 视觉方向

`styles.css` 已统一为：

```text
纸感手账 × 轻手绘贴纸 × 情绪签章
```

具体包括：

- 奶油纸背景
- 轻颗粒纸感
- 手绘贴纸式内嵌 SVG
- 低饱和配色
- 焦糖橙棕主按钮
- 朱砂印章点缀
- 胶带、邮戳、签筒、签纸元素
- 分享图预览弹层

### 3. 素材策略

当前第一版没有依赖外部图片切图，而是在 `app.js` 中内置了轻量 SVG 贴纸函数 `stickerSvg()`，用于生成：

```text
小狗 / 云朵 / 小花 / 星星 / 爱心 / 路牌 / 火苗 / 天平 / 杯子 / 嫩芽
```

这样做的好处：

- 不需要额外上传图片素材
- 页面加载更轻
- GitHub Pages 直接可运行
- 后续可逐步替换成独立 SVG 文件

## 当前验收重点

本轮先看：

1. 首页是否有点击欲。
2. 三个主题是否可爱、清晰、有区分。
3. 轻场景页是否像“选一句小纸条”，而不是问卷。
4. 抽签页是否有轻仪式感。
5. 结果页主句是否足够醒目，有截图欲。
6. 分享弹层是否像一张可保存的小纸条。
7. 整体是否避开了传统寺庙抽签和商务 App 感。

## 下一步

建议先打开线上页面检查移动端效果。如果视觉方向正确，再进行第二轮：

- 替换更精细的独立 SVG 素材
- 优化每个状态下的签文匹配规则
- 增加分享图真实导出能力
- 增加历史签章册页面
- 将静态 H5 迁移成 React / Vite 组件工程
