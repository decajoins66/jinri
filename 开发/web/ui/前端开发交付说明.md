# 今日灵签前端开发交付说明

> 适用对象：Codex / 前端开发 Agent / H5 原型开发  
> 项目阶段：第一版高保真可点击原型  
> 目标：快速开发一套“看起来像设计稿、能完整走通核心链路、便于朋友试玩反馈”的移动端页面。

---

## 1. 开发目标

《今日灵签》第一版前端开发的目标不是做完整商业产品，而是做一个可以用于验证的高保真 H5 / 小程序风格原型。

第一版重点验证：

- 首页主题是否有点击欲
- 轻场景句是否有代入感
- 状态选择是否顺滑
- 抽签动作是否有轻仪式感
- 结果页主句是否有“这句像我”的感觉
- 用户是否愿意点击“保存这句签”
- 分享图弹层是否自然

第一版不要做：

- 登录体系
- 用户账户
- 后端接口
- 真实内容推荐算法
- 会员体系
- 广告体系
- 社区功能
- 复杂埋点后台
- 复杂动画系统

---

## 2. 当前技术策略

当前仓库优先保留 `docs/` 静态 H5 版本，原因是：

1. `docs/` 可以直接用于 GitHub Pages。
2. 当前阶段重点是视觉和流程验证，静态 H5 足够。
3. 不引入构建链，降低部署失败概率。
4. 等视觉方向和链路验证后，再迁移到 React / Vite 更稳。

如果后续要升级工程，建议使用：

```text
Vite + React + TypeScript + CSS Modules
```

页面形态：

```text
宽度：100vw
最大宽度：430px
最小高度：100vh
居中显示
背景：奶油纸质感
```

---

## 3. 核心链路

第一版需要完成 7 个核心页面 / 状态：

```text
首页
↓
轻场景选择页
↓
状态选择页
↓
抽签页
↓
抽签过渡页
↓
结果页
↓
分享图弹层
```

分享图弹层不建议做独立路由，直接作为 `ResultPage` 内部的 `BottomSheet / ShareSheet` 组件。

---

## 4. 视觉方向

本项目采用：

**纸感手账 × 轻手绘贴纸 × 情绪签章**

整体感觉应该像一本温柔的小手账，也像一本咖啡店集章册。

关键词：

- 奶油纸
- 手绘贴纸
- 低饱和
- 小印章
- 小纸条
- 小胶带
- 小星星
- 松弛留白
- 情绪陪伴
- 可截图分享

不要做成：

- 寺庙抽签
- 塔罗占卜
- 严肃国风
- 商务 App
- 金融产品
- 高饱和卡通
- 大量复杂插画背景
- 重玄学算命广告

## 9. 页面开发说明

### 9.1 首页 HomePage

目标：让用户快速理解产品，并愿意点击一个主题入口。

结构：

```text
顶部：今日灵签 + 日期
中部：主标题 + 副标题
主题区：关系 / 选择 / 心境 三张卡片
底部：轻提示 + 小装饰
```

文案：

```text
今日灵签
5月31日 周六

今天想先聊哪一块？

不替你拿主意，
只想在你有点乱的时候，
给你一句能听进去的话。

关系
没说出口的话

选择
卡在两个答案之间

心境
先把自己安顿一下

不一定替你解答什么，但也许能让你心里顺一点。
```

点击逻辑：

```text
HomePage → ScenarioPage
```

### 9.2 轻场景选择页 ScenarioPage

目标：让用户选择一句最像当前处境的话。

结构：

```text
顶部：返回按钮
标题：当前主题名
副说明：主题说明
选项区：3 个场景卡片
底部：页码 1/3 或轻提示
```

设计要求：

- 卡片像贴在纸上的便签。
- 每张卡片可以配一个小贴纸插画。
- 点击后出现轻微选中态。
- 不要做成严肃问卷。
- 右侧可以使用小圆勾，选中后变成朱砂橘红。

点击逻辑：

```text
ScenarioPage → StatePage
```

### 9.3 状态选择页 StatePage

目标：用当前状态增强结果页代入感。

结构：

```text
顶部：返回按钮
标题：这件事，让你现在更像哪种状态？
状态区：4 个状态卡片
底部：页码 2/3 或轻提示
```

文案：

```text
这件事，
让你现在更像哪种状态？

有点上头
脑子里全是这件事

正在犹豫
两边都有道理，选不出来

已经有点累了
不想再想了，想要一个答案

想稳一点
不想冒险，想知道最安全的做法
```

点击逻辑：

```text
StatePage → DrawPage
```

### 9.4 抽签页 DrawPage

目标：建立轻仪式感，让用户愿意点击抽签。

结构：

```text
顶部：返回按钮
标题：静一下，抽出今天这支签
中间：签筒主视觉
底部：抽这一签按钮
辅助文案：相信第一直觉
```

点击逻辑：

```text
DrawPage → DrawingPage
```

### 9.5 抽签过渡页 DrawingPage

目标：补足等待感，避免硬切结果。

结构：

```text
中部：落下来的签纸
文案：签正在落下来
副文案：别急，再等一下。
```

跳转逻辑：

```text
DrawingPage -- 1.2s delay --> ResultPage
```

### 9.6 结果页 ResultPage

目标：让用户觉得“这句有点像我”，并愿意保存。

结构：

```text
顶部：第 17 签 + 慢慢靠岸 + 小印章
主句：大卡片
解释区：这支签想说 / 提醒你 / 你可以试试
底部：保存这句签 / 换个问题再抽一次
```

设计要求：

- 主句卡片必须是视觉中心。
- 主句字号要大，留白要足。
- 解释区块不要太重。
- 可以加一个“今日灵签”圆形印章。
- 结果页整体要适合截图。

点击逻辑：

```text
保存这句签 → 打开 ShareSheet
换个问题再抽一次 → HomePage
```

### 9.7 分享图弹层 ShareSheet

目标：让用户自然保存或转发。

结构：

```text
半屏弹层 / 底部弹层
标题：保存这句签
关闭按钮
分享图预览
按钮：保存到相册 / 发给朋友看看
```

设计要求：

- 弹层背景为暖白纸片。
- 背后页面加半透明暗色遮罩。
- 分享图预览像一张独立纸卡。
- 可以有胶带、小印章、小星星。
- 分享图主体不要放太多内容。
- 按钮圆润，像贴纸按钮。

  | "home"

第一版可以不接路由，直接用 step 控制页面。

## 13. 验收标准

### 13.1 视觉验收

- 页面整体是否是奶油纸感
- 是否有手绘贴纸感
- 是否低饱和、温柔、可爱
- 是否没有传统玄学 / 算命广告感
- 卡片是否像纸片，而不是商务卡片
- 装饰是否克制
- 结果页主句是否足够醒目
- 分享图是否有保存欲

### 13.2 交互验收

- 首页点击主题后能进入场景页
- 场景页选择后能进入状态页
- 状态页选择后能进入抽签页
- 抽签页点击后进入过渡页
- 过渡页 1.2 秒左右进入结果页
- 结果页点击保存能打开分享弹层
- 分享弹层能关闭
- 换个问题再抽一次能回到首页

### 13.3 移动端验收

- iPhone 13/14/15 普通尺寸显示正常
- 小屏幕不出现主要内容截断
- 底部按钮不被安全区遮挡
- 文字不溢出
- 弹层高度合理

## 14. 给 Codex 的开发提示词

```text
请根据 docs/产品方案.md、docs/ui/视觉风格规范.md 和 docs/ui/前端开发交付说明.md，为《今日灵签》开发一版移动端 H5 高保真可点击原型。

技术栈优先使用 Vite + React + TypeScript + CSS Modules。如果当前仓库仍采用 docs 静态 H5，则优先保证 docs 版本可直接运行。第一版不需要后端、不需要登录、不需要真实保存图片，只需要完成完整前端链路：首页 → 轻场景选择页 → 状态选择页 → 抽签页 → 抽签过渡页 → 结果页 → 分享图弹层。

视觉风格为“纸感手账 × 轻手绘贴纸 × 情绪签章”。整体要温柔、可爱、低饱和、松弛、有纸张纹理和手绘贴纸感。不要做成传统寺庙抽签、塔罗占卜、严肃国风、商务 App 或高饱和卡通风。

请优先用 CSS 实现卡片、按钮、圆角、阴影、纸感背景、弹层和交互动效。手绘贴纸、印章、签筒、签纸等可以先用简单 SVG 或占位图实现。页面要适合手机端预览，最大宽度 430px，居中显示。

开发时请注意：结果页是核心，主句必须是视觉中心；分享图弹层要像一张可以保存的小纸条；整体流程控制在轻快、顺滑、15-25 秒可以走完。
```

## 16. 重要提醒

Codex 开发时容易出现的问题：

1. 过度使用通用 UI 组件，导致像普通 App。
2. 卡片太硬，失去纸片感。
3. 图标太模板化，缺少手绘贴纸感。
4. 页面太满，失去松弛感。
5. 结果页文案层级不够突出。
6. 分享图塞太多内容，降低截图欲。
7. 做成中式抽签，偏离“情绪手账”方向。

修正原则：

- 减少元素
- 放大主句
- 增加留白
- 降低色彩饱和度
- 让卡片更像纸片
- 让装饰更像贴纸
- 让页面更像一本小手账
